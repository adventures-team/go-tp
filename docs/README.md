# go-tp

Обработчик очередей queued на Go - аналог перлового `MR::TP`. Библиотека делает то же, что в перловых проектах
делает связка `MR::TP` и `MR::Queue`: читает события из шардов queued по iproto, раздаёт их обработчикам через пул
воркеров, публикует события из продюсеров (веб-сервисов и т.п.), берёт конфигурацию из onlineconf и перечитывает
её на лету, отдаёт метрики и пишет логи через `log/slog`. Формат событий совместим с перловым: поддерживаются
перловый формат с аддонами `MR::TP::Addon::*` (CreationTime, Retry, Retry2, Producer) и Protobuf, поэтому
обработчики на Go и на перле могут обслуживать одни и те же очереди.

Режимы работы:

- **обработчик** (`tp.InitProcessor`) - процесс сам читает конфигурацию очередей и управляет пулом воркеров;
- **управляемый обработчик** (`managed/master`) - слотами процесса управляет перловый queue manager (`qm`),
  как и перловыми обработчиками;
- **продюсер** (`tp.InitProducer`) - только публикация событий, без обработчиков.

Документация API - на [pkg.go.dev](https://pkg.go.dev/github.com/adventures-team/go-tp) и в
[DOCUMENTATION.md](DOCUMENTATION.md); пример полного приложения - в `test/examples`.
Утилиты: `cmd/queued-stresser` - нагрузочное тестирование queued, `cmd/queued-mover` -
[перенос событий между кластерами queued](#queued-mover-перенос-событий-между-кластерами-queued).

## Конфигурация обработчиков очередей

Все значения перечитываются в рантайме. Имя инстанса задаётся в командной строке, остальные параметры задаются только в onlineconf.
Можно запустить произвольное кол-во обработчиков с одним именем инстанса, все количественные характеристики - per-instance.
Динамического управления кол-вом обработчиков нет (горутины дешёвые) - запускается указанное в конфиге кол-во горутин, при изменении этого кол-ва происходит запуск дополнительных горутин,
либо остановка запущенных (когда они будут свободны). Из-за невозможности мониторинга расхода памяти на конкретные горутины (даже средствами профайлера), задаётся два значения - 
soft OOM, при превышении которого происходит уменьшение кол-ва обработчиков на указанный коэффициент (но не менее 1 обработчика на очередь), и hard OOM, при котором новые задания
не обрабатываются, и при окончании обработки процесс выходит.

Обязательные параметры проверяются при запуске, при их отсутствии обработчик не запустится.
Логгирование осуществляется в stdout.

**$ProjectRoot** - путь, куда указывает передаваемый объект конфига (пример: /project/queued).

Настройки соединения с сервером (константы `queuedclient.Conf*`). Смена адресов при том же числе шардов
применяется на лету, изменение числа шардов требует рестарта.
* **$ProjectRoot/queueds/multi** - список (через запятую) серверов очередей, один сервер - один шард
* **$ProjectRoot/queueds/multi/timeout** - таймаут одной попытки запроса в секундах (default: 2)
* **$ProjectRoot/queueds/multi/retry_count**, **retry_delay** - повторные попытки при ошибках (default: 6, 300ms)
* **$ProjectRoot/queueds/multi/redial_interval**, **ping_interval**, **min_pid** - см. godoc `queuedclient`

`$ProjectRoot/tp/go` - глобальные настройки, могут быть переопределены per instance.
* **log_level**: уровень логгирования (advslog.ParseLevel; поддерживаются имена уровней zerolog)
* **log**: (опционально) поддерево пер-пакетных уровней логгирования, подключается опцией `tp.WithLogLevelConfig(module.Subtree("/tp/go/log"))`. Оверрайд для пакета - ключ `log/<import-path>/level`, например `log/github.com/adventures-team/go-iprotoconn/level = debug` задаёт уровень логгирования iproto-транспорта отдельно от прикладных уровней. Поддерево должно раздаваться с child lists (ключи `<path>/` со списками детей - пример в build/local/config.yaml); ключ `log/level` создавать **нельзя** - глобальным уровнем владеет **log_level**. Опция действует только без `tp.WithLogger` и должна попасть в первый вызов advslog.Init процесса.
* **oom_soft_limit**: размер инстанса в памяти (runtime.MemStats.Sys), по достижении которого начинается уменьшение кол-ва обработчиков. Формат размера: голое число (в т.ч. дробное) - байты; суффиксы kB/MB/GB/TB/PB - степени 1000, KiB/MiB/GiB/TiB/PiB - степени 1024, регистр не важен ("1.5GB", "512MiB")
* **oom_soft_downscale_rate**: коэффициент уменьшения кол-ва обработчиков всех очередей при достижении размера **soft_oom**, минимальное кол-во обработчиков - 1 (default: 0.5)
* **oom_hard_limit**: размер инстанса в памяти, при достижении которого прекращается обработка новых событий, и процесс выходит.
* **oom_check_period**: интервал проверки свободной памяти (синтаксис - https://pkg.go.dev/time#ParseDuration) (default: 1m)
* **workers_max_per_queue**: абсолютный максимум воркеров, даже если для очереди задано больше (для тушения аварий, < 0 - значение не используется, 0 - тушим всё)
* **workers_max**: абсолютный максимум воркеров всех очередей (для тушения аварий, < 0 - значение не используется, 0 - тушим всё)
* **workers**: дефолтное кол-во воркеров, если не переопределено для очереди
* **defer_time**: дефолтная задержка при ошибках обработки (синтаксис - https://pkg.go.dev/time#ParseDuration) (default: 5m)
* **defer_time_jitter**: рандомная добавка к задержке при ошибках обработки (синтаксис - https://pkg.go.dev/time#ParseDuration) (default: 1m)
* **initial_delay**: задержка обработки для новых событий (синтаксис - https://pkg.go.dev/time#ParseDuration) (default: 0)
* **fetch_batch_size**: аналог events per iteration - максимальное кол-во событий, получаемых из queued за раз (default: 10)
* **update_batch_size**: кол-во событий для delete/defer (default: 1000)

`$ProjectRoot/tp/go/$InstanceName` - настройки инстанса.

* **queue_ids**: id обрабатываемых очередей. Должны быть вкомпилены в обработчик запущенного инстанса с таким именем, про неподдерживаемые очереди будет сообщение в лог,
  инстанс продолжит обрабатывать поддерживаемые очереди.
* все глобальные настройки можно переопределить per instance.

`$ProjectRoot/tp/go/$InstanceName/$QueueID` - настройки очереди. Переопределить для очереди можно только указанные настройки.
* **workers**: количество обработчиков.
* **defer_time**: дефолтная задержка при ошибках обработки (синтаксис - https://pkg.go.dev/time#ParseDuration). Переопределяет значение заданное глобально, либо для инстанса. (default: 5m)
* **initial_delay**: задержка обработки для новых событий (синтаксис - https://pkg.go.dev/time#ParseDuration) (default: 0)
* **fetch_batch_size**: аналог events per iteration - максимальное кол-во событий, получаемых из queued за раз. Переопределяет значение заданное глобально, либо для инстанса (default: 10)
* **update_batch_size**: кол-во событий для delete/defer (default: 1000)

## queued-mover: перенос событий между кластерами queued

`cmd/queued-mover` переносит все события указанных очередей из одного кластера queued (A) в другой (B):
читает активные события из шардов A, публикует их в B как есть (тело события не декодируется, формат
безразличен) и удаляет из A. Типовой случай - переезд проекта на новый кластер: продюсеры и обработчики
уже переключены на B, хвост событий в A надо дотащить. Подробности - godoc `cmd/queued-mover` и
`internal/mover`.

```
bin/queued-mover -subtree /project/queued-mover [-module <name|path>]
```

* **-subtree** - обязательный: поддерево onlineconf с настройками утилиты.
* **-module** - модуль onlineconf (имя в /usr/local/etc/onlineconf или путь к cdb-файлу); по умолчанию -
  переменная окружения `CDB_CONFIG_FILE`, если она не задана - `TREE`.

Кластеры задаются в поддеревьях `src` и `dst` в том же формате, что `$ProjectRoot/queueds`:

* **$Root/src/queueds/multi** - список шардов A через запятую (и рядом необязательные `queueds/multi/timeout`
  и т.д., как выше)
* **$Root/dst/queueds/multi** - то же для B

Параметры утилиты (перечитываются на лету: либо при использовании, либо - `queue_ids`, `workers`, `log_level` -
по изменению поддерева, SIGHUP и раз в `stat_period`):

* **queue_ids** - очереди для переноса, формат как у `/tp/go/queue_ids` (обязателен)
* **one_shot** - `1`: выйти, когда во всех очередях A по статистике не осталось событий - ни активных, ни отложенных,
  ни заблокированных (default: 0 - работать как сервис, пока не придёт SIGTERM/SIGINT)
* **preserve_ids** - `1`: переносить события с исходными ID (default: 0, см. предупреждение ниже)
* **workers** - горутин на очередь (default: 1)
* **fetch_batch_size** - событий за один запрос с каждого шарда A (default: 100)
* **initial_delay** - задержка активации перенесённого события в B (default: 0)
* **defer_time** - на сколько откладывать в A событие, которое не удалось опубликовать в B (default: 1m)
* **poll_delay** - пауза после пустой выборки и после пачки с ошибками (default: 1s)
* **stat_period** - период строки прогресса в логе (default: 1m)
* **log_level** - уровень логгирования (default: info)

Гарантия - at-least-once: сначала публикация в B, потом удаление из A; падение между ними даёт повторный
перенос после переактивации события в A по таймауту блокировки queued. Отложенные события A переносятся
по мере их активации (queued отдаёт клиенту только активные события), в режиме one-shot утилита их ждёт.
Перед переносом обработчики A следует остановить (они конкурируют с утилитой за события), продюсеры -
переключить на B.

Коды выхода: 0 - штатное завершение, 1 - ошибка конфига или соединения, 2 - ошибка командной строки,
3 - one-shot прерван сигналом до опустошения очередей.

**preserve_ids** - переносить события с исходными ID. **Внимание: это может привести к коллизиям ID в
кластере B - как при переносе, так и позже.** queued назначает ID автоинкрементом отдельно в каждом шарде,
поэтому: (1) события из разных шардов A могут иметь одинаковые ID - при переносе они попадают в один шард B,
второе из них не переносится и остаётся в A с ошибкой `collision` в логе; (2) ID, выданные queued B после
переноса (или уже выданные раньше), могут совпасть с перенесёнными: публикация такого события в B завершится
ошибкой `wrong item`, а с `IgnoreDuplicateItems` (`FlagIgnoreWrongItem`) будет молча проигнорирована -
событие продюсера пропадёт. Включайте только когда ID событий генерирует приложение (`EventIDBuilder`),
они уникальны и обязаны сохраниться - например, в ID упакованы данные (`tp.Unpacker`) или по ID
обеспечивается идемпотентность. По умолчанию (`preserve_ids = 0`) ID назначает queued B, коллизии невозможны.
